
# NEXUM PC CLUB Shell

Клиент компьютерного клуба в браузере. Не SaaS, не касса, не прод с эквайрингом — учебный фронт оболочки ПК, которую гость видит, сев за машину: два счёта, тарифы, сессия, чат с админом, роли и простая аналитика.

Интерфейс кабинета нарочно близок к типичному LAN-шеллу (LANGAME / аналоги): тёмная «оболочка», слева рейка, справа тарифы, снизу ряд системных кнопок. Это **не** форк и **не** продукт Colizeum или LANGAME. Названия, логотипы и платёжные шлюзы чужие не используются.

Стек нарочно плоский: HTML, CSS, JS без сборки, без npm, без бэкенда. Состояние живёт в `localStorage`. Так проще отдать репозиторий, открыть с флешки и не объяснять Docker человеку, который пришёл посмотреть UI.

---

## Что умеет, коротко

- Регистрация и вход.
- Основной счёт (₽) и бонусный счёт. С каждого демо-пополнения **5%** уходит бонусами.
- Тарифы на этом ПК. Старт сессии списывает пакет, минуты тикают, стоп возвращает остаток.
- Чат гость ↔ персонал.
- Блокировка: срок, причина, имя админа. На входе в кабинет — модалка, из которой можно только написать персоналу или выйти.
- Две роли персонала: обычный админ и главный (`owner`).
- Персонал играет в том же кабинете, что и гость. Панель не отдельный «админский сайт», а выдвижной слой слева под логотипом.
- У owner — начисление **реальных** рублей, бан на 10 лет, выдача/снятие роли админа, таблица всех клиентов, график пополнений и прибыли за 7 дней.

Оплата учебная. Поля «карты» никуда не уходят. Не подключайте это к живым деньгам.

## Быстрый старт

Репозиторий нужно открывать **через HTTP**, не как `file://`. Относительные пути (`../styles`, `../scripts`) работают, но часть браузеров капризничает с модулями/хранилищем на `file://`. Проще так:

```bash
git clone https://github.com/MOOVMENT1337/MyPcClubClinet.git
cd MyPcClubClinet/html
python3 -m http.server 8080
```

В браузере: `http://localhost:8080/index.html`.

Любой статический сервер годится (`npx serve html`, Live Server в VS Code, nginx). Корень раздачи — каталог `html/`, иначе сломаются `../scripts` и `../assets`.

Если кабинет «пустой» или логин не принимает сиды — смотрите ключ хранилища. Сейчас это `nexum-club-v3`. Старые ключи (`v2` и ниже) этот код не читает. Сброс:

```js
localStorage.removeItem("nexum-club-v3");
location.reload();
```

Сиды появятся заново.

## Учётные записи из коробки

| Роль | Email | Пароль |
|------|--------|--------|
| Главный админ | `owner@nexum.local` | `owner123` |
| Админ | `admin@nexum.local` | `admin123` |
| Гость | регистрация на экране входа | любой ≥ 4 символов |

Это демо-логины, не секреты. В проде так не делают. Пароли лежат в `localStorage` открытым текстом — для учебного клиента достаточно, для продакшена это дыра.

После логина все роли попадают в `cabinet.html`. `admin.html` оставлен редиректом, чтобы не ломать старые закладки.

Чтобы увидеть чат и бан, откройте две вкладки: в одной owner/admin, в другой свежесозданный гость. Хранилище общее на origin, «realtime» — это опрос раз в 1–3 секунды, не WebSocket.

## Модель денег (это важно)

В клубах постоянно путают «баланс», «бонусы» и «время». Здесь три сущности, не две.

**Основной счёт (`money`)**  
То, что гость «кладёт картой» (демо) или что owner начисляет руками. Идёт в оплату тарифа первым.

**Бонусный счёт (`bonus`)**  
Не покупается картой. Источники:

1. 5% с суммы демо-пополнения.
2. Ручное начисление любым админом.

При оплате тарифа, если основного счёта не хватает, добираем бонусами. Если не хватает суммы двух счетов — отказ, сессия не стартует.

**Минуты (`minutes`)**  
Кредит времени. Появляются после оплаты тарифа или если админ накинул минуты без денег. На старте сессии весь кредит уходит в таймер (`session.leftMs`). На стопе остаток пересчитывается обратно в минуты.

Схема списания тарифа:

```
need = tariff.price
fromMoney = min(money, need)
fromBonus = min(bonus, need - fromMoney)
если остаток > 0 → отказ
иначе minutes += tariff.mins
```

В леджер:

- `topup` — пришло на основной счёт (это «касса», ещё не прибыль).
- `sale.profit` — сколько **реальных** рублей съел тариф. Бонусная часть в прибыль не кладётся, иначе вы нарисуете себе маржу из подарочных ₽.
- `gift_money` — owner подарил баланс. В выручку не мешаем: это не платёж гостя.

Если открыть «Стат» до первой продажи, график будет плоский. Это нормально.

## Тарифы

Зашиты в `scripts/store.js`, константа `TARIFFS`. Меняете цены — меняете этот массив, отдельного админского редактора нет.

| id | Название | Цена | Минуты |
|----|----------|------|--------|
| `base` | Базовый тариф | 170 ₽ | 60 |
| `p3` | Пакет 3 часа | 470 ₽ | 180 |
| `p5` | Пакет 5 часов | 700 ₽ | 300 |
| `night` | Ночь 22:00–8:00 | 810 ₽ | 600 |
| `morning` | Утро 08:00–12:00 | 340 ₽ | 240 |
| `day` | День 12:00–17:00 | 470 ₽ | 300 |

Окна «утро/день/ночь» сейчас подписи, не валидатор часов. Можно купить ночной пакет в полдень. Если понадобится жёсткое окно — это отдельная задача, не «ещё одна кнопка».

Выбор тарифа подсвечивается в правом списке. **Начать сессию** берёт выбранный. Повторный клик по кнопке — стоп.

Тик кабинета — `setInterval(..., 1000)`. Закрыли вкладку — JS не тикает, но `startedAt` и `leftMs` абсолютные: при следующем заходе `tickSession` догонит реальность и при необходимости закроет сессию.

## Роли и права

Три роли, не две. `owner` — не «админ с галочкой», а отдельный уровень. Обычный админ **не** видит других админов и owner в таблице. Owner не может быть забанен из UI.

| Действие | Гость | Админ | Owner |
|----------|:-----:|:-----:|:-----:|
| Играть, пакеты, демо-пополнение | да | да | да |
| Чат | да | да | да |
| Начислить минуты | — | да | да |
| Начислить бонусы | — | да | да |
| Начислить реальные ₽ | — | — | да |
| Бан на N часов | — | только `user` | `user` и `admin` |
| Бан на 10 лет | — | — | да |
| Выдать / снять админа | — | — | да (не себя, не owner) |
| Таблица клиентов | — | только гости | все кроме себя |
| Графики кассы | — | — | да |
| Кнопки слева под лого | — | Админ | Админ + Стат |

Заблокированный гость логинится, но кабинет сразу перекрыт модалкой: кто забанил, когда, до какого срока, за что. Сессия при бане рвётся.

## Кабинет, как им пользоваться

1. `index.html` — вход / регистрация.
2. `cabinet.html` — шелл ПК.
3. Слева: логотип, у персонала кнопки панели, пустая колонка (баннер убран специально), колокольчик, переключатель темы.
4. Сверху: ФИО, статус «СТАНДАРТ», кнопки «Тарифы» / «Чат с админом».
5. Сессия и два счёта.
6. Два баннера-заглушки «скоро будет контент клуба / софта».
7. Нижний ряд: рабочий стол, игры, проблема, старт сессии, выход. Первые две — заглушки с пояснением, «проблема» шлёт готовое сообщение в чат.

Тема (`light` / `dark`) пишется в `nexum-theme`, не в основной БД.

Панель персонала — `#adminDrawer` поверх стола, якорь слева от рейки. Закрывается своей кнопкой, кабинет при этом не разлогинивает.

```
│   ├── index.html      вход

│   └── admin.html      редирект на cabinet.html
├── scripts/
│   ├── store.js        домен: юзеры, деньги, сессия, леджер
│   ├── cabinet.js      UI гостя / игрока
│   ├── admin.js        UI персонала (молчит, если роль user)
│   └── app.js          наследие, кабинет его не подключает
├── styles/
│   ├── shell.css       актуальные стили оболочки
│   └── style.css       старый файл, в текущих html не подключён
├── assets/             баннеры и фото залов

```

Точка входа в данные — `window.Nexum` из `store.js`. Страницы не ходят в `localStorage` в обход, кроме темы.

Порядок скриптов в кабинете обязательный: `store.js` → `cabinet.js` → `admin.js`. Админский скрипт читает `Nexum.current()` и, если это гость, просто не вешает обработчики.

## Хранилище

Ключ: `nexum-club-v3`. Один JSON на origin.

```
{
  users: [ User ],
  sessionEmail: string | null,
  chats: { [userId]: Message[] },
  ledger: LedgerEntry[],
  notifications: []
}
```

Пользователь (сжато): `id`, `role` (`user` | `admin` | `owner`), `name`, `email`, `pass`, `money`, `bonus`, `minutes`, `status`, `blocked`, `session`, `history[]`, `createdAt`.

Блок: `byId`, `byName`, `reason`, `until`, `forever`, `at`.  
Сессия: `startedAt`, `tariffId`, `tariffName`, `leftMs`.  
Чат: тред на `userId` гостя. Сообщения персонала пишутся в тот же массив.

Лимита размера нет, кроме квоты браузера (~5 МБ). Для демо хватает. Бэкапа нет: очистили сайт в настройках Chrome — клуба не было.

Смена схемы = новый ключ (`v4`, …) либо миграция в `loadDb()`. Слепой `JSON.parse` старого объекта без миграции — классический способ получить «у меня пропали админы».

## Аналитика owner

Считается только из леджера, не «сумма money всех юзеров». Иначе подаренные рубли и несписанный баланс выглядят как выручка.

- **Пополнения** — сумма `topup`.
- **Прибыль** — сумма `sale.profit` (реальные ₽, ушедшие в тариф).
- **Обороты тарифов** — номинал пакетов, включая оплату бонусами.
- **Клиенты / админы** — текущие роли, не история.
- Столбики — 7 календарных дней, синий = пришло, зелёный = прибыль.

График SVG-свободный: высоты div. Библиотеку чартов не тащили.

## Чего здесь нет (чтобы не ждали)

- Сервера, JWT, хеша паролей, CORS, мультиязычности.
- Настоящего эквайринга, фискализации, смены кассира.
- Карты зала и брони конкретного системного блока.
- Проверки «сейчас ночь, ночной пакет нельзя».
- Синхронизации между компьютерами: два браузера на одной машине — да; два ПК — два разных `localStorage`.
- `app.js` / `style.css` в бою. Не удалял — вдруг понадобятся куски со старого лендинга.

Если понадобится несколько клиентов сразу — выносите `store.js` на маленький API (даже JSON-файл на кассе лучше, чем localStorage на каждом ПК).

## Разработка

Правила, которые жалко нарушать в таком объёме кода:

1. Деньги — целые рубли, `Math.round`. Копейки в демо не нужны, float в кассе — зло.
2. Любое изменение баланса/ролей — через функции store, не `user.money +=` из UI.
3. Owner-only UI прячется классом `hidden`, но серверной проверки нет: «защита» только в `store.js`. Это ок для демо, не ок для продакшена.
4. Не подключайте Cloudflare-скрипты и чужие счётчики в html — в какой-то момент они уже залетали в разметку и только мешали.
5. Кабинет должен открываться без персонала: `admin.js` не имеет права падать на `null` кнопке, если роль `user`. Сейчас обработчики вешаются только внутри `else` после проверки `isStaff`.

Стиль: `shell.css`, шрифт Manrope, акцент красный как у типичного клубного шелла. Светлая тема есть, но это не приоритет: клубные мониторы почти всегда тёмные.
